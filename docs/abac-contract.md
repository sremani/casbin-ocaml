# M6 typed ABAC contract

CB-303 delivers actual attribute-based enforcement with an explicit OCaml value model. Value.t is immutable String, finite float64 Number, Bool or Object (named values); schemas are TString, TNumber, TBool or TObject (named schemas). Object properties use case-sensitive ASCII identifiers. Duplicate, missing and extra properties, mismatched primitive types and nonfinite numbers are errors. Schemas themselves are validated, including unreachable properties. Schema/property traversal and expression nesting are bounded to 256 levels. There are no arbitrary object reflection, arrays, nulls or methods.

Enforcer.of_strings_abac/of_files_abac take request_schema naming every declared request field. Schema list order is immaterial; request values still follow model field order. enforce_values validates the complete request before evaluation. Existing string-only constructors and Expr APIs retain their established strictness. String enforcement on a typed snapshot wraps strings as Value.String and applies its schema; typed values on a legacy snapshot must all be strings. Management retains the compiled typed matcher and schema in each new snapshot.

Abac_expr is separate from the legacy compiler. It supports nested r.field.Property paths checked against the schema; p fields remain strings. It supports finite decimal number literals (including negative values, .5 and 1.), supported string literals, booleans, same-primitive == and !=, numeric or string < <= > >=, Boolean conditions/logic/parentheses, string-only keyMatch and two-/three-string g calls selected by role arity. Object comparisons, mixed-type comparisons, implicit numeric coercion, scientific/hex matcher literals, unary positive plus, arithmetic, eval, indexing, arrays and custom functions fail at compile time. Existing quoted-literal preprocessing/date restrictions remain in force. Comparison chains follow upstream left associativity at one precedence; each intermediate result is statically typed. Negative decimal literals allow ASCII whitespace after the minus. Every branch is statically validated and every nested policy reference counts in uses_policy.

Evaluation preserves resolver errors, operand order and Boolean short circuit. Role/domain callbacks use the existing validated graph, and policy effects/synthetic rows follow the same enforcer path. The upstream real-row selector also recognizes textual p_ anywhere in matcher source (including a literal or request property); actual AST uses_policy remains reference-based. Empty policies still use a synthetic row. Whole-request/schema validation is a deliberate stricter boundary than Go's dynamic lookup/type behavior on skipped branches; explicit oracle expectations record these cases.

## Differential probe protocol

The verification-only OCaml abac_probe takes MODEL POLICY and reads exactly two lines: a schema line and a request line. Each begins with a decimal count. A schema field is its UTF-8 name encoded as hex, followed by its recursive schema: s, n, b, or o followed by property count and name/schema pairs. A request value is s plus hex string, n plus decimal float, b plus true/false, or o plus property count and hex name/value pairs. Tokens are tab-separated. Empty strings are empty hex tokens; each entire line ends with newline. Arrays use a/count/value tokens and null uses z only to prove explicit unsupported request rejection; these do not create public OCaml value constructors.

The Go probe takes MODEL POLICY and reads a JSON array, unmarshals it into native strings/float64/bools/maps, then calls actual upstream Enforce. It does not enable heuristic JSON reinterpretation of opaque strings. Both probes return a single true/false line on success, or exit 2 with empty stdout and a diagnostic on error. Each manifest case supplies schema, native JSON request, expected OCaml result and separately observed Go result when stricter boundaries differ; neither side is skipped.

Acceptance: owner attributes and nested attributes, numeric thresholds/float64 behavior, booleans/string ordering, strict schema/type failures, missing attributes, role/keyMatch/domain/effect combinations, synthetic/request-only rows, and immutable management are covered.
