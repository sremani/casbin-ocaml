# M4 keyMatch contract

Add the built-in Boolean `keyMatch(key, pattern)` to the current string-valued matcher language. Accept exactly two string operands (fields, supported literals, or parenthesized strings); validate all branches at compile time. Existing literal exclusions and Boolean/string typing remain in force. The function does not require a role definition and composes with roles, Boolean operators, policy effects and immutable management.

Pinned source: `upstream/casbin/util/builtin_operators.go`, KeyMatch and KeyMatchFunc, lines 171–193; function registration in `model/function.go`. With no `*` in the pattern, compare the complete strings. Otherwise find the first asterisk by byte index and require the key to start with the bytes preceding it. The star matches zero or more bytes; all later pattern text is ignored. Thus `/foo*` matches `/foo` and `/foobar`, `/foo/*` requires `/foo/`, and `*ignored` matches every key including the empty string.

Matching is case-sensitive and byte-based. There is no regex, path decoding, slash normalization, escape handling, Unicode normalization or new dependency. Values from request/policy fields may contain arbitrary bytes; model literals keep the established restrictions. `keyMatch2` and all other matching functions remain unsupported, including in unreachable branches. Policy references in either operand must participate in `uses_policy`, preserving synthetic-row behavior for empty policy and request-only matchers.

Acceptance: independently observed Go cases cover first-star/ignored-suffix behavior, exact and mismatching prefixes, empty strings, Unicode and control values, argument validation, roles/effects, empty-policy/request-only evaluation, and management pattern additions/removals. OCaml regression tests cover resolver failures and short-circuit behavior as well as compile-time typing.
