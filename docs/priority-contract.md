# M7 priority effect and policy-order contract

CB-304 adds the standard priority(p.eft) || deny effect. In stored row order, the first matched determinate allow/deny wins; unmatched and unknown/empty explicit effects are skipped. Missing eft means implicit allow, and no determinate match means deny. Empty-policy and request-only synthetic-row behavior, including the textual p_ selector, follows the existing Go-compatible path. The enforcer stops immediately on the first determinate priority match, preserving errors from earlier evaluated rows while skipping later evaluation.

Without a policy field exactly named priority, load order and append order determine priority. With that field at any position, Go stably sorts policy rows by ascending numeric priority at load regardless of effect type, and inserts new rows after existing numeric ties. Smaller numbers win under the priority effect. Removal preserves remaining order. Raw strings define existing comma-joined duplicate keys; numeric equality does not collapse distinct raw priority spellings.

The numeric grammar is optional ASCII + or - followed by one or more ASCII decimal digits, within signed 64-bit range (matching the verified 64-bit Go oracle). Leading zeroes and signed zero are accepted; whitespace, empty text, hex, underscores and overflow are errors. Validation applies to retained rows after file deduplication and to newly stored rows after add-policy duplicate detection. Has/remove/no-op duplicate additions preserve raw key semantics even when a caller supplies a nonnumeric priority that collides with a valid stored key. Failed new additions are atomic and all prior snapshots remain valid. Invalid stored priorities are an explicit strict boundary from Go's inconsistent invalid-value sorting, independently observed in corpus cases.

Scope includes string and typed ABAC snapshots, ACL, roles, exact domains, all supported effects, and immutable management. subjectPriority is a separate hierarchy-ordering feature and remains rejected; custom effects, field-index overrides, update/batch/filtered operations remain deferred.

Implementation interfaces: Priority.parse returns signed Int64; Priority.order stably validates/sorts rows with a declared priority field (or preserves order without it); Priority.insert validates/inserts a new stored row after equal priorities (or appends without one). These helpers return errors for missing priority cells rather than raising. Policy.of_string calls order after dedup. Enforcer.add_policy calls insert only after duplicate detection. No grouping ordering changes.

Acceptance: independently observed Go enforcement and management cases establish implicit/explicit ordering, equal/negative/large/signed priorities, raw identities, field position, missing/unknown eft, mismatching earlier rows, synthetic rows, mutation/removal order and strict invalid numeric boundaries. Existing formerly unsupported normal-priority cases become checked parity; subjectPriority cases remain explicit rejections. Unit tests exercise signed64 grammar/range, first-decision/short circuit, stable order and snapshot atomicity, including typed/domain composition. All suites, all three corpora, provenance, install build and independent cross-review pass before a local M7 commit.
