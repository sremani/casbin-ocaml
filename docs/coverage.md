# Casbin OCaml coverage inventory

This inventory describes a bounded implementation against Go Casbin revision `524f3f2dc9baef696d748db491d49b3055d359d1`. It is an API and behavior inventory, not a claim to implement all of Casbin. No compatibility percentage is inferred from lines of code, API counts, or passing case counts.

M1–M7 are verified and locally committed, most recently priority milestone `c079470`. All delivered features below passed the complete OCaml 5.5.0 unit, differential, install and provenance gates. The local release evidence is recorded in [release review](release-review.md) and [performance](performance.md).

## Strict boundaries within the supported feature families

1. All models have one r/p/e/m and optional single g; duplicate sections/definitions/fields, malformed identifiers, unsupported policy types and dangling/interrupted continuation fail. Supported effect tokens normalize ASCII whitespace. This is stricter than upstream overwrite/parser behavior; Unicode whitespace and Go's scanner line cap are not reproduced.
2. Legacy request/policy values remain strings. Legacy Expr accepts only string equality/inequality, Boolean logic, g and keyMatch. Numeric/property expressions require explicit typed constructors and schema; the legacy parser is not widened implicitly.
3. Supported quoted matcher literals exclude quote characters, brackets, `#`, `:`, assertion-like r/p-dot substrings and date-shaped substrings because upstream preprocessing/type conversion can change their meaning. Request/policy values retain arbitrary byte strings, including Unicode, commas, NUL, quotes and backslashes.
4. Typed ABAC validates every declared request value, including unused fields and skipped branches. Object names are case-sensitive ASCII identifiers; missing/extra/duplicate keys, wrong types, nonfinite numbers and schema/property depths beyond 256 are errors. Go's skipped dynamic lookup may accept some such inputs; separate oracle expectations retain that difference. Arrays, null and object comparisons are rejected.
5. Typed matcher literals are finite decimal float64 numbers, with optional negative sign and intervening ASCII whitespace. Scientific/hex matcher literals, unary plus and arithmetic are excluded. Data Number values may be encoded scientifically by the verification protocol. Comparators share precedence and associate left; each intermediate Boolean is statically checked. No number/string coercion is performed.
6. Role graphs reject newly stored explicit self edges and cycles atomically, both at load and during mutations. Upstream in-memory/domain cycle behavior differs; these are explicit boundary traces. Transitive enforcement follows the declared ten-edge bound; direct queries are not transitive closures.
7. Domain strings are exact and isolated, including empty domains. The matcher must express permission-domain equality when required. Models that trigger upstream automatic domain keyMatch registration are rejected according to its exact textual formatting trigger.
8. Policy/grouping identity remains upstream comma-joined raw field identity, including collisions. File loading retains the first joined-key row. Duplicate additions return the same snapshot with false before candidate validation, including colliding tuples that would otherwise be invalid. Removal keeps remaining row order.
9. Grouping removal rebuilds graphs from retained rows; upstream stale incremental graph edges after a colliding tuple removal are not emulated. Upstream NUL-delimited g memoization collisions are likewise not emulated; actual graph tuples determine OCaml membership. Both traces are checked explicitly.
10. A nonempty policy uses real rows when the matcher contains actual p references or textual `p_`, including inside a literal or request-property name. Empty policies/request-only selectors use a synthetic empty-string row with implicit allow. This preserves upstream behavior: an empty policy is not itself a deny guarantee, and deny override can allow a false synthetic matcher.
11. M7 priorities are optional ASCII sign plus decimal digits in signed64 range, with raw strings preserved for identity. Stable load ordering applies whenever the field is named priority, irrespective of effect. Invalid retained/newly stored numeric priorities are rejected; upstream invalid-value sorting has no consistent numeric order. Has/remove and duplicate additions still preserve raw-key identity. Subject priority is excluded.
12. Invalid arities and grouping availability fail immediately; failed operations retain prior snapshots. Go may store malformed rows and fail at later enforcement. Role query results are normalized by sorting for reproducibility.

## Evidence accounting and release criteria

The complete M7 gate ran OCaml 5.5.0, all unit suites and installation/provenance checks. It checked 684 enforcement cases (635 parity, 49 explicit rejections), 53 management sequences with 787 steps and 14 boundary sequences, and 270 typed ABAC cases (246 parity, 24 boundaries). Targeted suites include 111 matcher, 111,447 nonpriority effect, 191 management, 244 keyMatch, 166 domain, 206 ABAC and 1,685 priority checks. Counts identify evidence, not an additive measure of Casbin coverage.

`scripts/verify.sh` invokes the toolchain guard before build/network work, checks pinned clean upstream, builds Go runners around the actual library, runs Dune tests and independently checks enforcement, operation and native ABAC manifests. Boundary expectations run both sides; they are not skipped successes. `@install` and copied source/fixture provenance remain separate acceptance checks. Replacing the pinned upstream revision requires renewed source review and observed oracle evidence.

A release of this declared subset requires:

- M7 final unit/enforcement/management/ABAC gates, source/API/test cross-review and local milestone commit completed; no pending feature advertised as verified.
- Every supported surface and its meaningful composition covered by reproducible cases, including short circuit, effects, empty/synthetic rows, domain isolation, numeric ties/ranges and immutable snapshot/error behavior.
- Every declared stricter boundary represented by checked expectations where Go differs; no unexplained discrepancy or silent unsupported authorization.
- CLI/library usage and package installation verified on the declared OCaml 5.5 toolchain; errors remain distinct from false decisions.
- LICENSE/NOTICE and fixture provenance checked; coverage and omission inventory agrees with actual public signatures and contracts.
- Performance evidence recorded separately with workload, machine/toolchain, policy/role sizes, warmup/repetitions, timings and relevant allocations. Measured samples and their limits live in the performance report; the API inventory makes no broad superiority claim.

These criteria establish release quality for the declared subset; they do not imply all upstream models, public methods or deployments are covered.
